## 反馈时请提供这些信息

信息越全，定位越快。缺了前三项基本无法排查。

| 内容 | 从哪里看 |
| --- | --- |
| 浏览器版本 | 地址栏输入 `brave://version` |
| 出问题的用户配置文件名称 | 右上角用户图标 |
| 工具栏状态颜色 | 绿色、黄色还是红色 |
| 页面上的错误提示 | 请复制原文，不要转述 |
| 问题发生的大致时间 | 精确到分钟最好 |
| 复现步骤 | 你依次做了什么，第几步开始不对 |
| 截图 | 敏感信息请先遮盖，见下方 |

## 导出诊断包

诊断包能把浏览器的运行状态一次性打包，比截图有用得多。

1. 地址栏输入 `brave://diagnostics/`。
2. 阅读页面上的隐私说明。
3. 点击导出诊断包，保存下来的是一个 zip。
4. 连同上面那张表的信息一起发给技术支持。

```text
brave://diagnostics/
```

### 诊断包里有什么

- 产品名、版本号、源码修订号、是否官方构建
- 操作系统类型、版本、CPU 架构
- 用户配置文件的哈希标识，以及是无痕、访客还是普通配置文件
- 指纹身份是否启用和有效、schema 版本、字体和插件的数量、Canvas / 音频 / WebGL / WebGPU 各项保护是否开启
- 代理状态、协议类型、端口、是否保存过密码、最近一次的错误码

### 不会包含什么

代理地址和出口 IP 只以加盐哈希的形式记录，不是明文。代理用户名和密码完全不写入。

打包前浏览器还会把包内所有 json、jsonl、log、txt 全文扫一遍，一旦发现代理地址、用户名或出口 IP 的明文出现在任何文件里，导出会直接失败并报 `forbidden_text_detected`，而不是生成一个泄露信息的包。

::: danger 诊断包仍需谨慎处理
诊断包可能包含日志和进程内存片段。只发给可信的技术支持人员，不要公开上传。
:::

## 截图和录屏之前

发出去之前请遮盖这些内容：

- 代理地址、端口、用户名、密码
- 完整的出口 IP
- 已登录账号的用户名、手机号、邮箱
- 页面上的订单号、余额等业务数据

## 浏览器崩溃了

地址栏输入 `brave://crashes/` 可以看本地的崩溃记录。反馈时附上崩溃发生的时间，再导出一份诊断包。

```text
brave://crashes/
```
